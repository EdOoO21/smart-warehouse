1. **Что такое CI/CD pipeline? Какие этапы CI pipeline для микросервисов?**
   CI/CD pipeline — автоматизированный процесс сборки, проверки и доставки кода. CI обычно включает checkout кода, build, lint/static analysis, unit tests, integration tests, сборку Docker-образа, security checks и публикацию артефактов.

2. **Разница между unit, integration и E2E tests?**
   Unit tests проверяют отдельную функцию/класс без внешних зависимостей. Integration tests проверяют взаимодействие сервиса с БД/Kafka/Redis, а E2E tests проверяют полный пользовательский или бизнес-сценарий через несколько сервисов.

3. **Что такое Testcontainers?**
   Testcontainers — библиотека, которая поднимает реальные зависимости в Docker-контейнерах прямо во время тестов. Это удобнее ручного запуска, потому что окружение создаётся автоматически, изолированно и воспроизводимо.

4. **Как обеспечить изоляцию интеграционных тестов?**
   Используют отдельные контейнеры, отдельные БД/схемы, уникальные топики/ключи и очистку данных после теста. Очистка нужна, чтобы один тест не влиял на другой и результаты были стабильными.

5. **Что такое E2E тест?**
   E2E тест проверяет систему целиком: от входного API/ивента до конечного результата. В микросервисах он должен проходить через реальные сервисы, очереди, БД и проверять бизнес-сценарий полностью.

6. **Как сервис экспортирует метрики в Prometheus?**
   Сервис отдаёт метрики по HTTP endpoint, обычно `/metrics`, в Prometheus-формате. Prometheus периодически опрашивает этот endpoint и сохраняет значения.

7. **Что такое Grafana?**
   Grafana — инструмент для визуализации метрик, логов и алертов. Обычно её используют для дашбордов по состоянию сервисов и инфраструктуры.

8. **Что должно быть на инфраструктурном дашборде?**
   CPU, RAM, disk, network, latency, errors, throughput и состояние зависимостей. Для Kafka важны lag и throughput, для ClickHouse/Cassandra/PostgreSQL — latency, queries, connections, disk, errors, для Redis — memory, ops/sec, evictions, hit rate.

9. **Что такое нагрузочное тестирование?**
   Нагрузочное тестирование проверяет, как система работает под высоким трафиком. Инструменты: `k6`, `hey`, `locust`, JMeter, Gatling.

10. **Что такое SLI и SLO?**
   SLI — измеряемый показатель качества сервиса, например latency или error rate. SLO — целевое значение для SLI, например 99% запросов быстрее 300 ms.

11. **Как обеспечить отказоустойчивость при нагрузочном тестировании?**
   Нужно тестировать систему под нагрузкой и следить, чтобы она не деградировала критически. Параллельно проверяют latency, error rate, CPU/RAM, DB latency, Kafka lag, retries, timeouts и saturation.

12. **Почему CI pipeline должен падать при любой ошибке?**
   Ошибка в build, tests или validation означает, что качество кода не подтверждено. Если ошибки «проглатывать», в production может попасть сломанный или нестабильный код.

13. **Что такое consumer lag в Kafka?**
   Consumer lag — разница между последним сообщением в partition и тем, что уже обработал consumer. Высокий lag означает, что consumer не успевает обрабатывать поток, его мониторят через Kafka exporter, Prometheus и Grafana.
